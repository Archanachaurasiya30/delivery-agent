  <action>
    1. Create `backend/app/models/base.py`:
       - Base = declarative_base() using SQLAlchemy 2.0 mapped_column style
       - BaseMixin class with common fields: id (UUID, default=uuid4, primary_key), created_at (DateTime, server_default=func.now()), updated_at (DateTime, onupdate=func.now())
       - Use `Mapped[]` type annotations throughout (SQLAlchemy 2.0 style)

    2. Create `backend/app/models/team.py` - TeamMember model:
       - Fields: id (UUID PK), name (String 100, not null), email (String 255, unique, not null), role (String 50, default="developer"), capacity_hours_per_sprint (Integer, default=40), is_available (Boolean, default=True), created_at, updated_at
       - Relationships: tasks (back_populates, lazy="raise" for async safety)
       - __tablename__ = "team_members"

    3. Create `backend/app/models/task.py` - Task model:
       - Fields: id (UUID PK), title (String 200, not null), description (Text, nullable), status (String 20, default="backlog"), priority (String 10, default="medium"), assignee_id (UUID, ForeignKey to team_members.id, nullable), story_points (Integer, nullable), external_id (String 100, nullable, for mock integration reference), created_at, updated_at
       - Status values: backlog, todo, in_progress, review, done
       - Priority values: low, medium, high, critical
       - Relationship: assignee -> TeamMember (lazy="raise")
       - __tablename__ = "tasks"

    4. Create `backend/app/models/proposal.py` - Proposal model:
       - Fields: id (UUID PK), type (String 50, not null - e.g. "sprint_planning"), state (String 20, default="draft"), content (JSONB, nullable), reasoning (Text, nullable), confidence (String 10, nullable), created_by_agent (String 100, nullable), reviewed_by (String 100, nullable), reviewed_at (DateTime, nullable), prompt_log (JSONB, nullable), execution_result (JSONB, nullable), created_at, updated_at
       - State values follow ProposalState: draft, pending_review, approved, rejected, executed, failed
       - __tablename__ = "proposals"

    5. Create `backend/app/models/__init__.py` that imports and re-exports all models:
       - from .base import Base
       - from .team import TeamMember
       - from .task import Task
       - from .proposal import Proposal

    6. Create `backend/app/schemas/__init__.py` as empty (schemas added by Plans 03, 04).

    7. Set up Alembic:
       - Create `backend/alembic.ini` pointing to backend/alembic directory, using async driver
       - Create `backend/alembic/env.py` with async migration support:
         - Import all models via `from app.models import Base`
         - Use `target_metadata = Base.metadata`
         - Configure `run_migrations_online` with `connectable = create_async_engine(settings.database_url)`
         - Use `async with connectable.connect() as connection: await connection.run_sync(do_run_migrations)`
       - Create initial migration file `001_initial_schema.py` with all three tables

    8. Run migration: `alembic upgrade head`

    Important: Use `lazy="raise"` on ALL relationships to catch implicit I/O during development (Pitfall 1 from RESEARCH).
    Use `Mapped[]` type annotations everywhere (SQLAlchemy 2.0 style, not legacy Column()).
  </action>
