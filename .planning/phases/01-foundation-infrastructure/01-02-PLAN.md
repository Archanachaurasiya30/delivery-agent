Build the LLM provider abstraction layer (LiteLLM with fallback), Celery background task infrastructure, WebSocket real-time updates, and base agent skeleton. This is the async intelligence backbone.

Purpose: Requirements INFR-01 (async agent), INFR-02 (flexible LLM), and the non-blocking UI pattern all depend on this infrastructure. Without it, the agent has no way to call LLMs, process in background, or push updates to the frontend.
Output: Working LLM provider abstraction, Celery task queue, WebSocket manager, and a test agent endpoint that demonstrates the full async flow.
</objective>

  <files>

  <action>
    1. Create `backend/app/llm/base.py` - Abstract LLM provider interface:
       - `class LLMProvider(ABC)` with abstract methods:
         - `async def complete(self, messages: List[Dict], model: Optional[str] = None, response_format: Optional[Type[BaseModel]] = None) -> Union[str, BaseModel]`
         - `async def complete_structured(self, messages: List[Dict], response_model: Type[BaseModel], model: Optional[str] = None) -> BaseModel` (convenience method)
       - Include provider metadata: `name`, `default_model`, `is_available` property

    2. Create `backend/app/llm/litellm_provider.py` - LiteLLM implementation:
       - `class LiteLLMProvider(LLMProvider)`:
         - Constructor takes Settings object, configures LiteLLM Router
         - Build model_list from settings: include OpenAI, Anthropic, Azure OpenAI entries based on which API keys are configured (skip providers without keys)
         - Configure fallback chain based on available providers
         - `complete()` method: calls `await litellm.acompletion()` via Router
         - `complete_structured()` method: calls complete with response_format, parses result with Pydantic model_validate_json
         - Error handling: catch litellm exceptions, wrap in custom LLMError
         - Retry logic: 3 retries with exponential backoff (use LiteLLM's built-in)
         - Timeout: 60 seconds default, configurable

    3. Create `backend/app/llm/factory.py` - Provider factory:
       - `def create_llm_provider(settings: Settings) -> LLMProvider`
       - If settings.llm_provider == "litellm": return LiteLLMProvider(settings)
       - Raise ValueError for unknown providers
       - Create module-level `llm_provider` singleton: `llm_provider = create_llm_provider(settings)`
       - Also export `get_llm_provider()` FastAPI dependency

    4. Create `backend/app/llm/__init__.py`:
       - Export: LLMProvider, LiteLLMProvider, create_llm_provider, get_llm_provider

    Important: Do NOT hardcode API keys. Read from Settings. If a provider key is empty/None, exclude that provider from the Router. This way the system works with just one configured provider.
    Important: Use `await litellm.acompletion()` (async), never `litellm.completion()` (sync). This is critical for the async-first architecture (Pitfall 3 from RESEARCH).
  </action>
  <verify>
    Run: `cd /Users/dev/Desktop/repos/delivery-agent/backend && python -c "

    Expect: Imports succeed, provider created without error (may warn about missing API keys, which is fine for test).
  </verify>
  <done>

    - LiteLLMProvider uses LiteLLM Router with automatic fallback between configured providers
    - Factory creates provider based on settings.llm_provider config

    - All LLM calls use async (acompletion)
  </done>

    1. Create `backend/app/tasks/celery_app.py`:
       - Celery app with broker=settings.redis_url, result_backend=settings.redis_url
       - Task time limits: soft_time_limit=300, time_limit=360 (5-6 min for LLM operations)
       - Task serializer: json
       - Configure task routes (all agent tasks to "agent" queue)
       - Include beat schedule placeholder for future scheduled tasks

    2. Create `backend/app/tasks/agent_tasks.py`:
       - `@celery_app.task(bind=True, max_retries=3)` decorated task
       - `def process_agent_request(self, proposal_id: str, request_type: str, payload: dict)`:
         - Creates new async event loop (Celery workers are sync by default)
         - Calls async helper: `asyncio.run(_process_agent_request(...))`
       - `async def _process_agent_request(proposal_id, request_type, payload)`:
         - Create new AsyncSession (NOT shared, per Pitfall 7)
         - Load proposal from database
         - Create LLM provider via factory
         - Call agent.process() with payload
         - Update proposal state to pending_review with agent output
         - Broadcast update via WebSocket manager (Redis pub/sub)
         - Handle exceptions: update proposal state to failed, retry with countdown=60

    3. Create `backend/app/agents/base.py` - Base agent:
       - `class BaseAgent`:
         - Constructor: takes LLMProvider instance
         - `async def process(self, payload: dict) -> dict`: abstract-ish method (raise NotImplementedError)
         - `async def _call_llm(self, messages: List[Dict], response_model: Optional[Type[BaseModel]] = None)`: wrapper around provider.complete() with logging
         - System prompt property (override in subclasses)
       - `class EchoAgent(BaseAgent)`:
         - Simple test agent that echoes back the payload with a timestamp
         - Used for testing the full async pipeline without needing real LLM keys

    4. Create `backend/app/ws/manager.py` - WebSocket connection manager:
       - `class ConnectionManager`:
         - `active_connections: Dict[str, List[WebSocket]]` (keyed by channel)
         - `async def connect(websocket, channel="default")`
         - `async def disconnect(websocket, channel="default")`
         - `async def broadcast(message: dict, channel="default")` - send to all on channel
         - Handle disconnected clients gracefully (remove on send error)
       - Module-level singleton: `ws_manager = ConnectionManager()`

    5. Create `backend/app/api/v1/ws.py` - WebSocket endpoint:
       - `@router.websocket("/ws/updates")` endpoint
       - Accept connection, add to manager
       - Keep alive loop with ping/pong
       - Clean disconnect handling

    6. Create `backend/app/api/v1/agent.py` - Agent API endpoints:
       - `POST /api/v1/agent/request` (status_code=202):
         - Accept: `{"type": "echo", "payload": {...}}`
         - Create Proposal record in database with state="draft"
         - Dispatch Celery task: `process_agent_request.delay(proposal_id, type, payload)`
         - Return: `{"proposal_id": "...", "status": "processing"}`
       - `GET /api/v1/agent/proposals/{proposal_id}`:
         - Return proposal with current state and content
       - `POST /api/v1/agent/proposals/{proposal_id}/approve`:
         - Transition proposal state from pending_review to approved
       - `POST /api/v1/agent/proposals/{proposal_id}/reject`:
         - Accept rejection reason, transition to rejected

    7. Register new routers in `backend/app/api/v1/router.py`:
       - Add agent router and ws router to the v1 router

    Important: The Celery task runs in a sync worker. Use `asyncio.run()` to bridge to async code. Create a NEW AsyncSession inside the task (never share sessions across tasks - Pitfall 7).
    Important: For v1, the EchoAgent is sufficient to test the pipeline. Real LangGraph agents come in Phase 3.
