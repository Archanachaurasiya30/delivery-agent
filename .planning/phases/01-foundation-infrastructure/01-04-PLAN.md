  <name>Task 1: Task management API with pluggable mock integration layer</name>
  <files>
    backend/app/schemas/task.py

  <action>
    1. Create `backend/app/schemas/task.py` - Pydantic schemas:
       - `class TaskCreate(BaseModel)`:
         - title: str (min_length=1, max_length=200)
         - description: Optional[str] = None
         - status: str = "backlog" (Literal["backlog", "todo", "in_progress", "review", "done"])
         - priority: str = "medium" (Literal["low", "medium", "high", "critical"])
         - assignee_id: Optional[UUID] = None
         - story_points: Optional[int] = None (ge=1, le=21 if provided)
         - external_id: Optional[str] = None
       - `class TaskUpdate(BaseModel)`:
         - All fields optional for partial updates
       - `class TaskResponse(BaseModel)`:
         - All model fields including id, created_at, updated_at
         - model_config = ConfigDict(from_attributes=True)
       - `class TaskListResponse(BaseModel)`:
         - tasks: List[TaskResponse]
         - total: int
       - `class TaskStatusCount(BaseModel)`:
         - status: str, count: int
       - `class TaskSummary(BaseModel)`:
         - total: int, by_status: List[TaskStatusCount], by_priority: dict

    2. Create `backend/app/integrations/task_provider.py` - Abstract interface:
       - `class TaskProvider(ABC)`:
         - `async def list_tasks(self, page: int = 1, page_size: int = 50) -> TaskPage`
         - `async def get_task(self, external_id: str) -> Optional[ExternalTask]`
         - `async def sync_tasks(self) -> List[ExternalTask]` (import tasks from external system)
       - `class ExternalTask(BaseModel)`: external_id, title, description, status, priority, assignee_name
       - `class TaskPage(BaseModel)`: items, total, page, page_size, has_more
       - These types represent the external system's view of tasks (different from our internal Task model)

    3. Create `backend/app/integrations/mock_task_provider.py` - Mock implementation:
       - `class MockTaskProvider(TaskProvider)`:
         - Generates realistic sample tasks: 15-20 tasks with varied titles, descriptions, statuses, priorities
         - Task titles should be realistic software dev tasks: "Implement user authentication", "Fix pagination bug", "Add export to CSV feature", etc.
         - `sync_tasks()` returns all mock tasks
         - `list_tasks()` returns paginated subset
         - Include simulated failure modes per RESEARCH Pitfall 8:
           - 1% chance of RateLimitError
           - 0.5% chance of timeout
           - Proper pagination support
       - This is NOT a database-backed provider. It generates data in memory.

    4. Create `backend/app/services/task_service.py` - Business logic:
       - `class TaskService`:
         - Constructor takes AsyncSession
         - `async def list_tasks(self, skip=0, limit=50, status=None, priority=None, assignee_id=None) -> Tuple[List[Task], int]`:
           - Support filtering by status, priority, assignee
         - `async def get_task(self, task_id: UUID) -> Task` (404 if not found)
         - `async def create_task(self, data: TaskCreate) -> Task`:
           - If assignee_id provided, verify team member exists (404 if not)
           - Create Task, flush, return
         - `async def update_task(self, task_id: UUID, data: TaskUpdate) -> Task`:
           - Load task, apply partial update, return
         - `async def delete_task(self, task_id: UUID) -> None`
         - `async def get_summary(self) -> dict`:
           - Return counts by status and priority
         - `async def import_from_provider(self, provider: TaskProvider) -> List[Task]`:
           - Call provider.sync_tasks()
           - For each external task, create Task if external_id not already in database
           - Return list of newly imported tasks

    5. Create `backend/app/api/v1/tasks.py` - API endpoints:
       - `router = APIRouter(prefix="/tasks", tags=["tasks"])`
       - `GET /tasks` -> TaskListResponse
         - Query params: skip, limit, status (optional), priority (optional), assignee_id (optional)
       - `POST /tasks` -> TaskResponse (status_code=201)
       - `GET /tasks/summary` -> TaskSummary
       - `GET /tasks/{task_id}` -> TaskResponse
       - `PATCH /tasks/{task_id}` -> TaskResponse
       - `DELETE /tasks/{task_id}` -> 204
       - `POST /tasks/import-mock` -> {"imported": N, "tasks": [...]}
         - Creates MockTaskProvider, calls import_from_provider
         - Useful for populating database with sample data

    6. Create `backend/app/integrations/__init__.py` with exports.

    7. Register tasks router in `backend/app/api/v1/router.py`.

    Important: The abstract TaskProvider interface should be designed based on what a real Azure DevOps API would look like (pagination, rate limits, external IDs), not based on mock simplicity. This is critical per RESEARCH Pitfall 8.
    Important: `import_from_provider` uses external_id to deduplicate, so importing twice doesn't create duplicates.
  </action>
